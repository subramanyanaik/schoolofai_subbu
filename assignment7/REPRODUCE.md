# Reproduce

Everything in `results/` and `figures/` is regenerated by the commands below.
Run them from `assignment7/`.

## 1. Environment

```bash
pip install torch numpy tiktoken pytest matplotlib pyarrow datasets
```

`datasets` is needed only for the corpus paths (`prepare_data.py`,
`build_ood_corpus.py`). Everything that carries evidentiary weight — the test
suite, E1, E2, E3, the parameter audit — runs without it and without a GPU.

Behind a TLS-intercepting corporate proxy also install `truststore`; `data.py`
picks it up automatically. It makes `huggingface_hub` validate against the OS
certificate store instead of certifi's bundle, and it does **not** disable
verification. Without it you get `CERTIFICATE_VERIFY_FAILED`.

`tiktoken` downloads the GPT-2 encoding on first use, so the very first run
needs network access even offline-ish paths.

E1, E3 and the parameter audit exit non-zero if a gate fails. They are

is wrong.

## 3. Corpus

```bash
python experiments/prepare_data.py --source fineweb --tokens 26000000
```

Streams `HuggingFaceFW/fineweb-edu` sample-10BT, tokenizes with GPT-2 tiktoken,
and writes `data/fineweb_train.bin` / `data/fineweb_val.bin` as uint32 already
remapped into `PackedVocab` order. Validation is the first 4,000 documents;
training skips them, so the two are disjoint. Took 1.4 minutes here.

The out-of-domain corpus for E7:

```bash
python experiments/build_ood_corpus.py
```

## 4. Training experiments

Run in this order — E4 writes the checkpoints E6, E7 and E8 consume.

```bash
python experiments/e4_train_arms.py --tokens 5001216
```

```bash
python experiments/e5_d_sweep.py --tokens 1500000
```

E5 finds that the configuration E4 ran is the sixth-best of seven. Re-run the
three KAS arms at the one it recommends. `--tag` keeps these checkpoints
separate so they do not clobber the ones E6/E7/E8 were measured from; A0 and A1
are omitted because `d_c`/`L_max` cannot affect them:

```bash
python experiments/e4_train_arms.py --tokens 5001216 --d-c 64 --L-max 32 --arms a2_kronf_kas,a3_kronf_kas_tied,a4_kas_unigram --tag _dc64L32 --out e4_best_config.json
```

```bash
python experiments/e7_ood_multiscript.py
```

```bash
python experiments/e8_token_buckets.py
```

```bash
python experiments/e6_vocab_swap.py
```

```bash
python experiments/make_figures.py
```

**Pin `--tokens` if you want numbers comparable to ours.** Without it, E4 runs
a calibration probe and picks a budget from measured throughput on your GPU, so
a faster or slower card trains every arm for a different number of tokens. Use
`--budget-min N` only when you do not care about matching another machine and
just want the arms compared fairly against each other — that path is still
token-matched *within* the run, which is the property E4 actually tests.

`e5_d_sweep.py` merges into its results file, keyed by `(d_c, L_max)`. A
timed-out invocation can be resumed by simply re-running it; completed
configurations are skipped. Pass `--redo` to start over.

## 5. Reference hardware

| | |
|---|---|
| GPU | NVIDIA GeForce RTX 3050 Laptop, 4.3 GB |
| torch | 2.5.1+cu121 |
| Python | 3.12.6 |
| OS | Windows 11 |

Batch size 8 is not a default, it is a measurement: 16 and 24 are both *slower*
on this card because it spills at 4.3 GB. On a larger card try `--batch-size
16` and expect different absolute bits-per-byte.

`KRON_FORCE_CPU=1` forces the CPU path for every script.
