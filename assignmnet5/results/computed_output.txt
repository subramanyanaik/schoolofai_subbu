8 · PROXY EXPERIMENTS — THE PLAN AS A TESTABLE HYPOTHESIS
==============================================================================

  [P1] Indic synthetic parity cap  (3B, 0.060T/arm, 2 arms, ~1,517 GPU-h, ~$3,792)
      H : Capping synthetic Indic at <=1.0x native beats a synthetic-heavy arm on native-quality metrics at matched compute.
      A : plan mixture (synthetic at the computed synthetic/native ratio)
      B : synthetic DOUBLED (2x the plan ratio), translated held constant
      M : MILU per Tier-1 lang; FLORES chrF++; 200-sample native audit
      -> Adopt the cap only if A beats B by >=2.0 pts mean MILU AND shows no chrF++ regression. If B wins, the cap RISES -- the plan was too conservative. If neither separates, drop the cap as unjustified machinery.

  [P2] Protected floor necessity  (1B, 0.020T/arm, 2 arms, ~169 GPU-h, ~$421)
      H : Without a native-only always-on floor, Indic capability drifts down during the code/math-heavy S2 phase.
      A : 8% native-Indic floor enforced every batch
      B : same global Indic share, no batch-level floor (selector free)
      M : MILU (hi + one Dravidian) at 5 checkpoints -- the CURVE SHAPE is the evidence. Secondary: HumanEval/GSM-mini to confirm no tax on dominant lanes.
      -> Keep the floor if B shows a mid-training MILU dip >=3 pts that A avoids. If both curves are flat, DROP the floor -- it is unnecessary complexity.

  [P3] Agentic verification gate  (1B, 0.020T/arm, 2 arms, ~169 GPU-h, ~$421)
      H : Execution-verified sandbox trajectories beat imitation-only public agent data at equal token count.
      A : sandbox self-play, kept only on task success
      B : public trajectories, no verification gate
      M : BFCL function-call accuracy; tau2-bench task success
      -> A must clear B by >=5 pts on BOTH. If not, the generation pipeline is the defect to fix before the 6% agentic share scales -- not a reason to cut the lane.

  [P4] Mixture-transition gradient stability  (3B, 0.060T/arm, 3 arms, ~2,275 GPU-h, ~$5,688)
      H : Ramping lane-share changes across a >=100B-token blending band prevents the ~150x gradient-norm spike V4 recorded on an abrupt Hindi share increase.
      A : 100B-token linear ramp between stage mixes
      B : abrupt step change at the stage boundary
      C : 20B-token ramp (is the band over-specified?)
      M : max gradient-norm multiplier over the transition; loss-spike count
      -> Keep the 100B band only if the abrupt arm spikes >=5x AND the 20B arm also spikes. If 20B is sufficient, shorten the band and reclaim schedule.

  [P5] Loss-masking on tool observations  (1B, 0.020T/arm, 2 arms, ~169 GPU-h, ~$421)
      H : Zero-loss masking of tool outputs prevents observation hallucination without costing task success.
      A : loss on model-generated tokens only (plans, code, JSON calls)
      B : loss on the full trajectory including tool responses
      M : rate of fabricated tool observations in held-out rollouts; BFCL
      -> A must cut fabricated-observation rate by >=50% at no BFCL cost. This is the cheapest proxy in the set and should run FIRST.

  Total proxy cost ~$10,743 (4,297 GPU-h) = 1.70% of the flagship run (~$631,951).
  Every ratio in this plan is a hypothesis until one of these fires.
